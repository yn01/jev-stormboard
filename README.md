# Jev × 東京の防災電文

気象庁の防災情報XML(防災電文)をリアルタイムに取り込み、TypeSafe の
[Jev](https://typesafe.jp/) で「**この電文は自分にとって何を意味するか**」を
判定させる Streamlit デモです。リポジトリ名は `jev-stormboard`。
防災電文は種類が多く構造も複雑なため、型で定義した判定ロジックを安全に書ける Jev が
向いていると考え、その題材として作っています。

> ## ⚠️ これはデモです
> **実際の防災判断には使わないでください。**
> 避難や行動の判断は、必ず[気象庁](https://www.jma.go.jp/)および
> お住まいの自治体の発表を確認してください。
> 本リポジトリは個人による技術デモであり、情報の正確性・即時性を保証しません。

## 現在の段階

- **第一段階: ロガー** — 防災電文を取得して保存し続ける(稼働中)
- **第二段階: 判定コア** — 保存した電文1本を Jev で判定する
- **第三段階(いま): 画面** — 電文が流れる中で Jev の判断が浮かび上がる様子を見せる

要件の一覧と進捗、デモの日程と本番当日の手順は [`requirements.md`](requirements.md)
にまとめてあります(Python の依存関係ファイル `requirements.txt` とは別物です)。

## セットアップ

Python 3.11 以上が必要です。

```bash
git clone https://github.com/yn01/jev-stormboard.git
cd jev-stormboard
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## ロガーの起動

```bash
source .venv/bin/activate
caffeinate -i python -m logger
```

`caffeinate -i` は MacBook のスリープを防ぐためのものです。運用時は
**電源に接続し、蓋は開けたまま**にしてください(蓋を閉じるとスリープします)。

ログは画面と `logs/logger.log` の両方に出ます(5MB ごとにローテーション、5世代)。

## 保存するもの

| フィード | 保存対象 |
| --- | --- |
| 随時 (`extra.xml` / `extra_l.xml`) | **全エントリ** |
| 定時 (`regular.xml` / `regular_l.xml`) | **全エントリ** |

地震火山フィードとその他フィードは取得しません。

定時フィードを種類で絞りたい場合は、`logger/config.py` の `REGULAR_TITLE_INCLUDES`
に文字列を並べてください(部分一致、いずれかに当たれば保存)。空のときはフィルタなしです。

```python
REGULAR_TITLE_INCLUDES: tuple[str, ...] = ("警報級の可能性",)  # 初期値は () = 全件
```

動作は次のとおりです。

- 高頻度フィードを **60秒間隔**でポーリング
- **起動時と1時間ごと**に長期フィードで穴埋め(停止していた間の分を回収)
- 重複は entry の id で排除。起動時に `data/index.jsonl` から保存済み ID を読み込むため、
  **再起動しても続きから保存**されます
- フィード取得は `If-Modified-Since` / `ETag` による条件付き GET(更新が無ければ 304)
- 電文本体のダウンロードは並列度 2、1件ごとに 0.2 秒待ち。気象庁のサーバーに負荷をかけません

随時フィードの新着が **30分以上途切れる**と、ログに WARNING を出します
(`NO_NEW_ENTRY_WARN_SEC`)。気象庁側が静かなだけのこともありますが、取得が
止まっていることに気づくための目安です。

長期フィードは7日分(約 7,500 件)を含むため、穴埋めで遡る上限を
`BACKFILL_MAX_AGE_HOURS`(初期値 24時間)で制限しています。これより長く停止していた分を
回収したい場合は、この値を一時的に大きくしてください。

## 保存形式

電文本体は gzip で保存します。日付は entry の `updated` を JST に直したものです。

```
data/raw/2026-09-19/20260918175015_0_VPWW53_030000.xml.gz
```

索引 `data/index.jsonl` には、1電文につき1行を追記します。

```json
{"id":"https://www.data.jma.go.jp/developer/xml/data/20260918175015_0_VPWW53_030000.xml",
 "title":"気象特別警報・警報・注意報","updated":"2026-09-18T17:50:14Z","author":"盛岡地方気象台",
 "feed":"extra","url":"https://...","path":"data/raw/2026-09-19/2026...xml.gz",
 "bytes":20079,"fetched_at":"2026-09-19T03:20:55+00:00","summary":"【岩手県気象警報・注意報】..."}
```

ファイルは一時ファイルに書いてから rename するため、途中で落ちても壊れたファイルは残りません。

## 保存状況と容量の確認

```bash
python -m logger.stats   # 件数、種類別の件数、日別の容量、最終の新着からの経過時間
du -sh data/             # 実際のディスク使用量
```

`stats` の「最終の新着からの経過時間」で、取得が続いているかを確認できます。
随時(extra)が 30分以上途切れていると、その旨が表示されます。

`data/` は数千ファイルになるため、`ls` や grep で中を探さず、
`index.jsonl` と `stats` で確認してください。

件数が極端に多い種類を `stats` で見つけたら、`logger/config.py` の
`TITLE_EXCLUDES` に文字列を足すと、その種類を保存しなくなります(部分一致、初期値は空)。

```python
TITLE_EXCLUDES: tuple[str, ...] = ("大雨危険度通知",)
```

定時フィードを種類で絞る `REGULAR_TITLE_INCLUDES` も同じファイルにあります(初期値は空 = 全件)。

## 停止と再起動

`Ctrl-C`(SIGINT)または `kill`(SIGTERM)で安全に停止します。取得中の電文を
中断し、書きかけのファイルを残さずに終了します。

再起動すると `data/index.jsonl` から保存済み ID を読み込むため、**重複せずに
続きから保存**されます。停止していた間の電文は、起動時の穴埋めで回収されます。

## 判定コア

保存した電文1本を Jev に渡し、「この電文はこの人にとって何を意味するか」を
10問まとめて判定します。

```bash
source .venv/bin/activate
python -m core.judge --latest                    # 最新の電文を判定
python -m core.judge --id 20260918223117_0_VPFJ50_120000   # 電文を指定して判定
python -m core.judge --latest --json             # 結果をJSONで出力
```

判定対象の人物は [`profile.yaml`](profile.yaml) に1件だけ書いてあります。
仮の内容なので、ご自身の状況に書き換えてください(書き換え箇所にコメントがあります)。

質問は `core/questions.py` の `QUESTIONS` リストに定義しています。
**リストに要素を足すだけで質問数が増えます。** 各質問には観点のタグ
(message / plan / prepare / move / home / family / action)が付いていて、
将来、観点ごとの絞り込みや画面でのグループ表示に使います。

10問すべてを **1回のリクエスト**にまとめて送るため、質問を増やしても
レイテンシはほとんど変わりません(10問で約600ms、11問でも約630ms)。

### Noul の確信度について

Jev の答えは型によって形が違います。

| 型 | 値 | 確率 | 確信度 |
| --- | --- | --- | --- |
| Choice | 選択肢名 | 選択肢ごとの確率 | `confidence` |
| Score | 数値 | 段階ごとの確率 | `confidence` |
| Noul | 0〜1 | 値そのものが確率 | SDKは返さない |

**Noul の値は「命題が真である確率」そのもの**で、Choice / Score の `confidence`
(モデルがその答えをどれだけ確信しているか)とは意味が異なります。
しきい値で絞り込むときは、Noul については `0.5` からの距離(`abs(値-0.5)*2`)を
確信度の代わりに使います。表では `*` 付きで表示されます。

### APIキー

`TYPESAFE_API_KEY` を使います。環境変数が未設定の場合は
`.claude/settings.local.json` の `env` から読みます(このファイルはコミットされません)。

## 画面(Streamlit)

```bash
cd ~/Dev/jev-stormboard      # ← このプロジェクトのディレクトリで
source .venv/bin/activate    # ← このプロジェクトの .venv を有効にする
streamlit run app/streamlit_app.py
```

ブラウザで http://localhost:8501 が開きます。

画面は**ダークテーマ**です(`.streamlit/config.toml`)。表示は **1秒ごと**に
更新されます(`app/streamlit_app.py` の `run_every`)。短くするほど Streamlit の
通信が詰まりやすくなるので、変えたときは一度通しで触って確認してください。

> **別プロジェクトの仮想環境で起動しないこと。**
> `.venv` を有効にし忘れたり、ほかのプロジェクト（jev-intent など）の
> `.venv/bin/streamlit` で起動すると、`streamlit` や `PyYAML` などが無くて
> `ModuleNotFoundError` になります。`which streamlit` で
> `jev-stormboard/.venv/bin/streamlit` が出ることを確認してください。
>
> 地図は自前の SVG なので、描画ライブラリは要りません。ロガーとは**別のプロセス**で動き、
`data/index.jsonl` は読み取りしかしません(ロガーを止める必要はありません)。

画面は上から3層に並びます。

1. **結論バナー** — いま取るべき行動を1つだけ大きく出します。副題に
   気象庁の警戒レベル相当を添えます。

   | 表示 | 副題 | 色 |
   | --- | --- | --- |
   | いつもどおりで | 平常の行動 | 緑 |
   | 予定の見直しを | 警戒レベル1 相当 | 黄 |
   | 早めの備えを | 警戒レベル2 相当 | 橙 |
   | 外出は控えて | 警戒レベル3 相当 | 赤 |
   | 早めの避難を | 警戒レベル4 相当 | 濃い赤 |

   **「相当」は目安です。** 警戒レベルは地域に対して行政と気象庁が出すもので、
   ここで出しているのは個人の行動なので別物です。発令そのものではありません。

   すぐ下に、切迫している・事象の深刻さ・生活への影響度の3つを小さく添えます
2. **速報欄** — 判定した電文を流します。**この画面の主役**です。直近7件を
   積み上げるので、電文が次々にさばかれていく様子がそのまま見えます。
   右上には**いま毎秒どれだけ判定しているか**(件/秒・問/秒)を出します。
   枠の色は、いちばん新しい判定の行動の色になります
3. **関連度マップ**(関東圏) — 下記
4. **注目の判定**(関連度が高い電文のカード)と**流れる電文**(判定した電文の一覧)
5. **Jev の性能**(処理件数・レイテンシ・質問数・トークン・コスト)— 画面下部の
   折りたたみ。「状況」ではなく性能を示す数字なので下に置いています

結論バナーの上には**動作モード**を常時表示します。ライブは緑の点が点滅し、
最終判定からの経過時間が出ます。リプレイは対象日と再生速度が出て、
画面の背景がうっすら紫になり、上下に紫の帯が出ます(本番中に見間違えないため)。

関連度が低い電文も一覧から消さず、薄く表示します。大量に流れる電文の中から、
自分に関係するものだけが浮かび上がる様子を見るためです。

### サイドバー

| 操作 | 内容 |
| --- | --- |
| 関連度のしきい値 | 「この地域に関係する」がこの値以上の電文を「注目の判定」に出す(初期値 0.5) |
| 判断がついた回答だけを濃く | Noul の確信度 `abs(値-0.5)*2` がこの値に満たない回答を、カード内で薄く表示する |
| 質問数 | 10問 / 30問 / 50問。切り替えるとその質問数で判定し直す |
| 動作モード | ライブ / リプレイ |
| 対象日 | リプレイ時のみ。保存済みの電文がある日から選ぶ |
| 開始時刻 | リプレイ時のみ。30分刻み。この時刻より前の電文は飛ばして再生する |
| 再生速度 | リプレイ時のみ。1倍 / 10倍 / 60倍 / 100倍 / 最速 |

### 動作モード

- **ライブ**: `data/index.jsonl` を5秒ごとに見て、新しく増えた電文を判定します。
  起動直後だけ、画面が空にならないよう直近20件をさかのぼって判定します。
- **リプレイ**: 指定した日の電文を、発表時刻の順に再生速度に応じて判定していきます。
  開始時刻を指定すると、その時刻より前は飛ばせます（台風が近づいた夕方から見たい、
  といった使い方ができます）。飛ばしたぶんの電文も画面には表示されるので、
  「その時刻時点の状況から始まる」という見え方になります。

モード表示の横に操作ボタンがあります。ライブは「いますぐ確認」(索引をすぐ見に行く)、
リプレイは「再生 / 一時停止 / 最初から」です。デモ中に説明しながら止められます。
「最初から」は再生位置を戻すだけで、判定結果は消しません(API を呼び直しません)。

判定は**バックグラウンドのワーカー**が進め、画面は `st.fragment` で描画だけを
2秒ごとに更新します。判定で画面が固まることはありません。

### 関連度マップ

**関東圏(1都6県＋山梨)**を都県ごとに塗ります。全国だと見たい関東が小さくなるためです
(範囲は `app/mapview.py` の `KANTO_CODES` で変えられます)。
**これは気象庁の警報マップではありません。**
色の濃さは「警報の強さ」ではなく、**Jev が判定した「自分にとっての関連度」**
(relevant)です。警報が出ている地域を塗るだけなら Jev は何も貢献していないので、
そこがこの地図の存在意義です。

2つの軸を、別々の見せ方で重ねています。

| 軸 | 表し方 | 出どころ |
| --- | --- | --- |
| **関連度** | 面の色（青 → 紫 → マゼンタ） | **Jev の判定** |
| **事象の深刻さ** | 中央の円の大きさ（琥珀 → 赤） | 電文から読める値 |

**色が濃い＝自分に関係する／円が大きい＝事象が深刻**です。両方そろった地域が
「自分にとって重大」だと一目で分かります。関連度にあえて赤や橙を使っていないのは、
警報の強さと見間違えられないようにするためです。

青い点滅はプロファイルの居住地です。

全国を対象とする電文(全般気象情報・台風情報・集約通報など)は、全国を一律に塗ると
地図が意味を失うため色には含めず、件数だけを地図の下に出しています。

地図は**自前の SVG**で描いています。形は変わらず色だけが変わるので、更新のたびに
一瞬消えるようなちらつきが出ません(色の変化は CSS の transition でなめらかにしています)。
描画ライブラリには依存しません。

地図が重い場合は、サイドバーの「関連度マップを表示」を外してください。

**地図の出典: 地球地図日本（国土地理院）。**
[dataofjapan/land](https://github.com/dataofjapan/land) が GeoJSON 化したものを
簡略化して `assets/japan_prefectures.geojson` に置いています(実行時に
ネットワークからは取得しません)。配布元の条件により、非営利利用では出典元
(地球地図日本)の明記が必要です。

### 質問数とレイテンシ

質問は `core/questions.py` に **50問**あり、サイドバーで 10問 / 30問 / 50問 を
切り替えられます。全問を1回のリクエストで送るため、**質問数を増やしても
レイテンシはほとんど変わりません**。

| 質問数 | レイテンシ | 入力トークン |
| --- | --- | --- |
| 10問 | 496ms | 5,162 |
| 30問 | 732ms | 8,006 |
| 50問 | 713ms | 11,103 |

画面の指標の帯には、質問数別の平均レイテンシが併記されます。切り替えて
見比べてください。

### 値の読み方

| 型 | 表示 | 意味 |
| --- | --- | --- |
| Noul | `0.85` とバー | 命題が真である確率(0〜1) |
| Score | `2.82 / 4` とバー | 5段階(0〜4)の評価。バーは目盛りに対する比率 |
| Choice | 上位2件の選択肢と確率 | 選ばれた選択肢 |

### 自分の状況で試すには

このリポジトリは public です。`profile.yaml` は**公開用の仮プロファイル**で、
東京都に住む会社員という架空の内容になっています。

自分の実際の状況で試すには、`profile.local.yaml` を作ってください。

```bash
cp profile.local.example.yaml profile.local.yaml
# 好きなエディタで profile.local.yaml を書き換える
```

`profile.local.yaml` があれば、アプリは**そちらを優先して読みます**。
このファイルは `.gitignore` に入れてあるので、**コミットされることはありません**。
どちらを読み込んだかは、画面の右上に小さく出ます。

| ファイル | 中身 | git |
| --- | --- | --- |
| `profile.yaml` | 公開用の仮プロファイル(架空) | コミットする |
| `profile.local.yaml` | 自分の実際の状況 | **コミットされない** |
| `profile.local.example.yaml` | 書き方の例 | コミットする |

公開用の `profile.yaml` では、地域を**東京都の府県予報区コード(130000)**まで
にとどめています。市区町村コードまで書いても判定の質はほとんど変わらないことを
確認済みです(詳しくは [`requirements.md`](requirements.md) の「公開の方針」)。
より細かい判定が欲しい場合は `profile.local.yaml` に市区町村コードを書いてください。

> **スクリーンショットを撮るときの注意**
> 画面の表示名は profile の `name` をそのまま出します。`profile.local.yaml` を
> 使っていると実名や市区町村が画面に出ることがあります。公開する画像を撮るときは、
> 画面右上の「読み込み元」が `profile.yaml` になっていることを確認してください。

書き換えて画面を再読み込みすると、そのまま反映されます。判定結果には
**どのプロファイルで判定したか**が記録されるので、書き換えると過去の判定と
前提が食い違う旨が画面に出ます。揃えたい場合は
`data/judged/judgements.jsonl` を空にしてください。

### コストとキャッシュ

判定結果は `data/judged/judgements.jsonl` に保存され、**同じ電文は二重に判定しません**。
リプレイを繰り返しても API のコストは増えず、画面を再読み込みしても履歴が残ります。
キャッシュは電文IDと**質問数**の組で持つので、質問数を変えるとその数で判定し直します。

推定コストは入力 $0.042/MTok で計算しています(1件あたり約4,000トークン、
10問で約250〜400ms)。APIのレート制限に当たった場合は画面にその旨を表示し、
処理を止めずに間隔を空けて再試行します。

## テスト

```bash
python -m pytest
```

フィードのサンプルを fixture にして、パース・フィルタ・重複排除・再起動時の復元を確認します。

## データの出典

[気象庁防災情報XMLフォーマット 情報提供ページ](https://xml.kishou.go.jp/)

利用にあたっては、気象庁の[利用規約](https://www.jma.go.jp/jma/kishou/info/coment.html)を
必ず確認してください。取得の間隔や並列度を上げると気象庁のサーバーに負荷をかけるため、
設定値は変更しないでください。
